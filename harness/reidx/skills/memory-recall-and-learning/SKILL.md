# Memory recall and learning loop

## Before work
- Use `memory_memory_search` with the task's key concepts and environment names.
- Read the most relevant matching memories, not the entire memory database.
- Check dates and whether facts may have changed.

## After substantial work
- Summarize what actually worked, what failed, why, and how it was verified.
- Search memory to avoid duplicates.
- Use `memory_memory_remember` for durable decisions, lessons, workflows or writing preferences.
- Keep task-specific sensitive material out of memory.

## Continuous learning
- If a verified method is reusable, draft a skill with `memory_memory_propose_skill`.
- A candidate should include trigger conditions, prerequisites, procedure, expected outputs, verification, failure handling and source/evidence.
- Do not create a skill for a one-off workaround or unverified guess.
- Never activate, overwrite or delete an active skill without explicit user approval.
